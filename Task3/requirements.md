# Список требований для интеграций с устройствами умного дома

## Требования к безопасности
- Передача данных осуществляется строго по протоколу HTTPS
- Персональные данные шифруются на клиенте (в мобильном приложении) и таким образом передаются на сервер. Сервер работает с зашифрованными данными, биометрия в открытом виде нигде не хранится. 
- Базы данных шлагбаумов и домофонов разделены
- Аутентификация и авторизация проходят во внутренних сервисах PropDevelopment (сервис аутентификации и сервисы управления домофонами и воротами соотвественно), от партнера приходят сырые данные (фото собственика или номера машины), партнеру предается только результат авторизации.
- Каждый вызов сервиса аутентификации журналируется, фиксируется зайдествовнное устройство (его id, ip адрес, API-ключ)

## Протоколы аутентификации и авторизации
- Аутентификация происходит на стороне уже существующего сервиса auth-service-1
- Для мобильного приложения авторизация для работы с домофоном происходит по REST-API и использованием JWT-токена пользователя на стороне сервиса управления домофоном.
- Для автоматического распознавания Собственника со стороны домофона, авторизация домофона и сервиса происходит по уникальному для каждого домофона ключу API
- Для мобильного приложения авторизация для работы с шлагбаумом просиходит по REST-API и использованием JWT-токена пользователя на стороне сервиса управления шлагбаумами.
- Для автоматического распознавания машины Собственника со стороны шлагбаума, авторизация шлагбаума и сервиса происходит по уникальному для каждого шлагбаума ключу API

## Взаимодействие между системами предприятия и внешней платформой
- Взаимодействия происходят строго с использованием SSL
- Любые взаимодействия происходят только при помощи токена авторизации
- Токены имеют TTL
